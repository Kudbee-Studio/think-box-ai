    01 · Dashboard

    A control room that never leaves your machine.

    The operator dashboard lives in apps/web: an Express + WebSocket web tier that binds to 127.0.0.1:3000. It is local-only today. Login, roles and HTTPS come later on the roadmap, before it is ever exposed .

    • Live agent status over WebSocket
    • Host and Origin checks on every connection
    • No public exposure until E6 (TLS deploy)

    02 · Agent runtime

    Goals become tasks. Tasks become evidence.

    The runtime breaks a goal into tasks, schedules them, and asks the governance backend before anything with side effects runs. The backend (FastAPI) , the action ledger and the receipts.

    • Layered stack, from foundation to agents
    • Draft or simulate is the default mode
    • : simulated · inferred · verified

    03 · Tools & plugins

    Every tool call is a request, not a command.

    Tools and plugins run through permission checks. A tool without an explicit permission level is treated as RESTRICTED. File tools stay inside the workspace, and shell_exec is off by default.

    • Approval gate before side effects
    • Workspace-confined file access
    • and Algorand (read-only) integrations

    04 · Local models

    Small and local first. Bigger only when needed.

    A router sends cheap work to a small local model and can fall back to Mercury 2. Token telemetry is recorded per route. Providers swap through config, with no provider SDK in runtime code.

    • Cheap route: local Ollama
    • Cloud route: the cheapest measured model
    • Per-route token telemetry

    05 · Memory

    Memory in one file you can back up.

    Persistent memory runs on SQLite: no server, one file, . Postgres (Neon) was tried and then . It only comes back if a measured scale criterion is met.

    • SQLite is the system of record
    • Hermetic tests, simple backups
    • Reopen criteria are written down, not guessed

    06 · Security & approvals

    The founder merges. Agents propose.

    Agents open proposals and the founder reviews and merges all work. At runtime the same idea applies: risky actions wait for a human, audit logs are append-only, and nothing is called "live verified" without real evidence.

    • Human-in-the-loop by default
    • Append-only action ledger
    • Four-state ladder: code complete → test verified → live verified → production ready

    The problem

    Powerful agents. No guardrails.

    They act without asking

    Many agent setups let a model run shell commands, write files or call APIs directly. One bad plan and the damage is already done.

    Nothing is accountable

    When something goes wrong, there is often no tamper-evident record of who asked, what ran and why it was allowed.

    Claims outrun evidence

    "It works" often means "it compiled." Think Box labels every capability claim, so a simulated result is never shown as a verified one.

    Model routing explainer

    Cheap and local first. Cloud when it is worth it.

    Pick a situation and watch which route a request takes. Telemetry is recorded per route, so you can see where the tokens went.

    Simplified. The real routing rules live in the code (PR #271: token telemetry + a small local route; PR #394: the cloud fallback is chosen from measured results, below). The fallback route sends the prompt to a remote provider, so it is not local-only.

    Measured, not guessed

    Which model fixes it, and what it costs.

    Each cloud model was run on the same frozen fixing tasks (27 easy and hard tasks, then pooled with earlier runs to 66). A fix only counts when the sandbox checks pass and an independent test agrees. Routing picks the cheapest model that cleared 90% over at least 20 tasks.

    ModelVerified fixesMedian cost per taskMedian timeCost basis

    Source: docs/evidence/p3.57-cost-per-task/ and the earlier runs it pools (PRs #388 to #397), read on Oct 7, 2026; a test recomputes the table from the committed files. The tasks are small frozen fixtures, not real repositories, and sampling is unseeded: one miss is noise, so the order of near-equal models is not a ranking of quality. DeepSeek's dollar figure uses an estimated price because it reports none. If a provider fails before a run has done anything, the same goal is retried on the next model and the dashboard says so.

    Security-first design
    
    
    Default deny, by design.
    
    
    
      
    ⌂
    Loopback only
    The dashboard binds to 127.0.0.1. Host and Origin headers are checked, so a random web page cannot drive your agent over WebSocket.
    
      
    ✋
    Approval gates
    Side effects pass admission first. Tools without a declared permission level default to RESTRICTED. A human approves risky actions.
    
      
    ⌘
    No shell by default
    shell_exec ships disabled. File tools are confined to the workspace, and paths outside it are refused.
    
      
    ≡
    Append-only ledger
    The action ledger and audit logs only grow. ADR 027 proposes hash-chained, signed audit rows next.
    
      
    ◎
    Evidence labels
    Claims are labeled simulated, inferred, verified or physically measured. CI never promotes anything to "live verified" on its own.
    
      
    ⇄
    Provider independence
    No provider SDKs in runtime code. Models swap through config, and no new external service is added without an accepted ADR.

    Planned Concept
    
      
    Think Tokens: what agents learn.
    
      
    In Think Box, a Think Token is a : a reusable pattern an agent picks up from a session, with a confidence score and counts of how often it was reused and how often it worked.
    
      
    The code exists but is not wired in. Tokens are held in memory and not saved, and the dashboard's learning panel is a simulation. ADR 028 proposes storing them in SQLite once the founder decides to connect them to agent sessions (roadmap E5).
    
      
      
    Not a cryptocurrency. The repo also has a strategy document for a separate economic token, but it shares only the name. Access is never decided by tokens. It comes from roles, grants and quotas. This site makes no claims about price, supply, chains or partnerships.

          FAQ
          
      
          Straight answers.
          
      
          If something here sounds too good, it is labeled. Ask anyway.
          
      
    
          
    
          
      
          Is Think Box production-ready?
          No. The repo uses a four-state ladder: code complete → test verified → live verified → production ready.  never promotes work to the last two on its own. The enterprise phases (E0–E6) are proposed, not done.
          
      
          Does my data leave my machine?
          The dashboard binds to loopback and the cheap route runs on a local model through Ollama. The cloud agents (Mercury 2, DeepSeek, xAI Grok) are remote providers: a goal that runs on one sends the goal and whatever the agent reads in its tool results to that provider, and the dashboard asks for approval before a goal that leaves the machine. A local model keeps everything on your machine.
          
      
          Is a Think Token a cryptocurrency?
          No. In Think Box, a Think Token is a learning unit: a reusable pattern with a confidence score (ADR 028). It is planned, not live. A separate economic-token idea exists in the repo, and tokens never decide access.
          
      
          Why SQLite and not Postgres?
          Zero config, one file, easy backups, and FTS5 covers search. A Neon setup was added and then reverted (ADR 026). ADR 027 lists measurable reopen criteria, such as multiple hosts sharing a store or sustained write contention.
          
      
          Who decides what gets merged?
          Agents propose changes as single-theme pull requests. The founder reviews and merges all work.
          
      
          Is the terminal demo real output?
          No. It is a scripted, illustrative session that explains behavior. Every ID, count and balance in it is a labeled sample value.
          
      
          Can I try it?
          The repository is public and MIT licensed, and the README has a quick start (Python ≥ 3.10, pip install -e ".[dev]"). Expect a fast-moving project.
