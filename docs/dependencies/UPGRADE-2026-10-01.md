# Dependency upgrade — 2026-10-01

Branch `chore/deps-upgrade`, one PR. Scope: `apps/web` npm dependencies, Python version floors and dev
tools, and the CI Actions inventory. Constraints kept: Node >= 22.6 supported, dashboard 127.0.0.1-only
with Host/Origin gating unchanged, SQLite (ADR 026), no new runtime services, no Vercel, no new
dependencies.

Every number below was measured on 2026-10-01 in this repository; commands are listed so they can be
repeated. Anything not measured is marked UNPROVEN.

### 1.1 Express 5 breaking changes, checked against this code

| Express 5 change | Finding here | Action |
|---|---|---|
| Path syntax (path-to-regexp 8: no bare `*`, no regex routes) | All routes are plain `/path/:param` (listed with `grep` over `app/router.METHOD(...)`) | none |
| `req.body` is `undefined` when there is no body (v4 gave `{}`) | Some handlers read `req.body.x` or destructure `req.body` unguarded | one-line shim after `express.json()` restores `{}`; test `a POST with no body at all is a 400, not a 500` in `tests/git-routes.test.ts` |
| `req.query` parser defaults to "simple" | Handlers read flat string/number query values only | none |
| Removed/renamed APIs (`req.param()`, `res.sendfile`, `res.json(status, body)`, `app.del`) | none used | none |
| Async handler rejections are forwarded to the error handler | handlers already catch and answer explicitly | none |
| `@types/express` 5 param typing | 22 type errors, all `req.params.id` / `taskId` in `server.ts` | one local alias `type Request = ExpressRequest<Record<string, string>>` in `server.ts` (every route uses plain named params). Route handler lines are left byte-identical to `main` on purpose: CodeQL's existing "missing rate limiting" alert #75 on the session-files route is matched by line content, and editing the handler line made it re-appear as a new alert |

## 3. CI (GitHub Actions)

`.github/workflows/test.yml` has one job, `web-typecheck`, and it already has `timeout-minutes: 15`.

| Action | Current | Latest | Risk | Status |
|---|---|---|---|---|
| actions/checkout | v4 | v7.0.1 | low (Node 24 runtime; runner >= 2.327.1; v6 moved credentials to a separate file) | **NOT APPLIED** |
| actions/setup-node | v4 | v7.0.0 | low (Node 24 runtime; v5+ only auto-caches when `package.json` has a `packageManager` field, which it does not) | **NOT APPLIED** |

Not applied because the `gh` token used here has scopes `admin:public_key, gist, read:org, repo` and no
`workflow`, so a push containing a workflow-file change would be rejected, and a rejected push wastes a CI
cycle. Suggested follow-up for someone with that scope (two lines):

```diff
-      - uses: actions/checkout@v4
+      - uses: actions/checkout@v7
...
-      - uses: actions/setup-node@v4
+      - uses: actions/setup-node@v7
```
