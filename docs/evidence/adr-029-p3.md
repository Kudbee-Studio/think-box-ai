## 3. Links and propagation

- Link kinds exist only where there is a mechanical evidence source (the bot's `builds_on`, `contradicts` (a negation-word heuristic) and `same_goal_family` were removed):
  `same_tool` (shared `tool:` tags), `similar` (normalized BM25 >= 0.25), `co_used` (same run; weight 0.3 + 0.2 per shared run).
  One row per pair and kind (ids stored in canonical order); idempotent; a ledger entry per create or update.
- Similarity calibration (real data, 13 Mercury lessons, 78 pairs): median 0.081, p90 0.224, max 0.322; 5 pairs at or above 0.25, all inside the create-then-verify cluster of near-duplicates. The bot's thresholds
  (jaccard 0.72, BM25 0.55 on an uncalibrated `/8` scale) never fire on this data (best real pair 0.425 on its scale, 0 pairs above 0.55). 0.25 is a calibration to real data, **not** a validated cut-off for paraphrase detection; paraphrase detection stays with the model's `novel` verdict.
- Live: a real run on the seed copy used TT-000005, TT-000011 and TT-000013 together; their history of earlier shared runs produced three `co_used` links with evidence `used together in 4 runs` / `5 runs`, 3 `link_create` ledger entries, and the ledger verified.
  The new token, TT-000019, was written by Mercury, challenged, accepted, and tagged `tool:list_files`.
- Propagation: using a token credits each directly linked token that was not itself used in that run (depth 1, so it cannot loop). Bonus = `min(0.10, 0.02 x sum of the last 12 credits)`, stored in `score_breakdown.propagation` and
  `propagation_bonus`; the displayed score equals the weighted components plus the bonus (test). Credits survive later rescoring (feedback, outcomes) and show in `get` and `list`.

## 5. Red-team pass

- Forged `think_token_*` events and malformed ids: unchanged from P1 (no new HTTP route; the WebSocket handler is untouched). `links` is read-only data in the token payload.
- Link and credit inputs are internal (ids come from the store; `upsertLink` refuses unknown tokens, self links and unknown kinds); evidence strings contain only tool names and numbers.
- Unsafe advice: five regex families fail a lesson even if a model approves. A lesson can still be unsafe in a way those patterns do not match; the model's skeptical challenge is the second line.
- A model outage cannot reject anything: no verdict leaves the token `scored`; re-challenge refuses to force a verdict.
- Secrets: nothing logged or committed; the live scripts read the `.env` key through the server and process environment only; the raw evidence JSON was grepped for key-like strings (none).

## 6. What was wrong with the bot's version (for the record)

17 type errors and failing tests; an A/B "proof" from a simulator whose success flag was `arm === 'on'` (the doc's numbers were not measured); an unconnected `rebuildLinks` (links never created in normal operation);
a re-challenge that built a fake run from the token title (so it failed every token) and force-rejected when no model answered; a redundant rejects table; propagation that did not reproduce the shown score and was wiped on the next rescore;
uncalibrated similarity thresholds; a cube mapping presented as a decided founder decision (it was not) and an ADR edited to "Accepted"; empty backup files presented as backups.
